# 手机消息和剧情同步（2026-11-18，Cora 提）

## 问题

剧本里有很多"发消息"的剧情（【手机：Ollie】"我很饿你"、学长凌晨五点的阿姆斯特丹、Ploy 的"家人们谁懂啊"、Kieran 的联机邀请……）。演完以后，手机里也要**真的有这些消息**。玩家之后再去聊天，能翻到；但这时候再回复，已经改变不了那个事件了。

## 现状（读过代码）

- `{ msg: { from, text, tr } }` 已经会把一条消息存进 `S.chats[from]`，只存 NPC 发的那一条。
- 剧情里玩家的选择**没有**存成"我"发的消息。
- 群聊、朋友圈的剧情消息没有地方存。
- 一段手机剧情里连着好几条消息时，要写好几个 msg，玩家选项夹在中间时没有对应写法。

## 规则

1. **剧本里所有【手机：某人】的段落，都按时间顺序写进那个人的聊天记录**，包括：
   - NPC 发的每一条（带「」翻译）；
   - 玩家选的那个选项，存成"我"发的消息。选项里〔〕和（）的说明文字去掉，只留引号里说出口的话；选项如果是动作（"发一条语音念给他听"），存成一条灰色的系统行："[语音 0:12]"；
   - 选项后面 NPC 的回复。
2. **只存玩家实际走过的那条分支**，没选的不存。
3. 每段剧情消息前面加一条日期分隔线：`—— 大一·秋 第6周 周二 23:40 ——`（时间用剧本里写的，没写就用"晚上"）。
4. **群聊**：剧本写【手机：小组群】【手机：flat 群】【手机：老乡群】的，存进对应群；群在聊天列表里已有的（广东老乡群、相亲相爱一家人）照用，没有的新建：小组群（第 3 周分组后）、flat 群（开局按住宿）。
5. **朋友圈**：剧本写【手机：朋友圈】的，存进朋友圈动态，按周排。学长、Kieran（两个号）、Ploy 的朋友圈兜底表（见各扩写文件）也进这里。
6. **剧情过了，回复不改剧情**：
   - 剧情消息后面，输入框照常能用，走普通 AI 聊天（照常有好感变化，按聊天规则算）。
   - 剧情消息存的时候带 `scripted: true`。给 AI 的上下文里，带这个标记的消息照常传进去，系统提示里加一句："以上带【已发生】的是之前已经发生过的事，可以自然地提起，但不要改写它的结果，也不要假装它没发生。"
   - AI 不许在回复里**承诺具体的未来安排**（"回头确认了发你""周六我带你去"），除非同时走邀约系统发出一张邀约卡。上次 Ollie 说"回头确认了发你"，之后什么都没发生，就是这个问题。
7. **剧情进行中，手机界面显示**：剧本里一段【手机】剧情演的时候，画面换成手机界面（和平时打开手机一样的样子），消息一条一条弹出来，选项显示成手机底部的回复按钮。演完自动收起手机，回到原来的画面。
8. **未读**：剧情消息是在剧情里看过的，存进去时算已读；朋友圈新动态算未读，手机图标上有小红点。

## 剧本写法（给策划自己，也给 coding 转换脚本用）

```
【手机：Ollie】（周三 23:12）
**Ollie**：你好！今天你吃饭了吗？
**Ollie**：我很饿你
→ 选项
- **认真纠正："是'我饿了，你呢？'……"** → 存成我发的消息
- **发一条语音，念给他听** → 存成 [语音]
【手机收起】
```

- 【手机：XX】开始，【手机收起】结束；中间所有台词和选项都按上面的规则存。
- 没有【手机收起】的，遇到下一个【背景：】时自动收起。

## 要改的数据

- `S.chats[id]` 里每条加：`scripted`（是不是剧情消息）、`week`、`time`、`kind`（text / voice / image / divider）。
- 新增 `S.groups`（群聊）和 `S.moments`（朋友圈）。
- 已经写好的剧本里所有【手机】段落，转换的时候都按这个规则转。我这边扩写文件里的【手机】段落已经是这个写法。
