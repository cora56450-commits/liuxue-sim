# AI 聊天防乱编（2026-11-18，Cora 提："怕 AI 写的时候乱编"）

## 一、AI 最容易乱编的五类东西

| 类 | 例子 | 后果 |
|---|---|---|
| 1. 人 | Kieran 说"我爸周末来看我"；学长说"我哥在伦敦" | 和设定冲突（Kieran 爸爸不提，学长没有哥） |
| 2. 过去的事 | Ollie 说"我们上次去约克玩得很开心"（其实没去过） | 玩家会以为自己漏了剧情 |
| 3. 未来的约定 | "回头确认了发你""周六带你去"（试玩时 Ollie 说过，之后什么都没发生） | 承诺落空 |
| 4. 地点和东西 | 编一家不存在的餐厅；编一个真实品牌、真实游戏名 | 和虚构城市、商标规则冲突 |
| 5. 关系越级 | 熟人阶段就说"我想你了"；告白前就以恋人自居 | 破坏阶段感 |

## 二、做法

### 1. 事实卡（每个角色一张）

- 攻略对象：`02_剧本/设定_攻略对象家人与生日.md` ＋ 原有人设＋专业年级（`人物关系与专业.md`）＋住处（`02_剧本/剧本_攻略对象住处设定.md`）。
- 朋友和 NPC：`characters.js` 的 persona ＋ `人物关系与专业.md` 里关于他的几行。
- 事实卡放进 `characters.js` 每个人的 `facts` 字段（一个字符串列表），聊天时整张传给 AI。
- 每张卡最后都有一行"**不能编的**"，照抄进去。

### 2. 系统提示里加的硬规则（加进 `AI.RULES`）

```
关于事实：
- 你只能提到事实卡里写了的人、地点、过去发生的事。没写的，一律不提、不编。
- 被问到事实卡里没有的事（家里人、过去、以后的打算），用符合性格的方式含糊过去或岔开话题，不要编一个答案。
- 你们之间发生过的事，只能提【已发生】标记的剧情消息和聊天记录里真实出现过的内容。
- 不提任何真实的品牌、店名、游戏名、明星；需要的话用泛称（"那家店""那个游戏"）。主机写 Swi○ch 2、P○5。
- 不做具体的未来约定（时间、地点、"回头发你"）。想约玩家，只能用 [[INVITE ...]] 标记；不写标记就不许约。
- 按关系阶段说话，不越级：没交往不说"我想你""我爱你"，没告白不以恋人自居。
- 外国角色只说英文，后面跟「中文」。
```

### 3. 回复以后程序再查一遍（不靠 AI 自觉）

拿到 AI 回复后，跑三个检查，任何一个不过就**重试一次**，再不过就用固定兜底句（`chatFallback`）：

| 检查 | 怎么查 |
|---|---|
| 人名白名单 | 回复里出现的人名（中文二到四字的专有称呼、英文首字母大写的名字），必须在白名单里：所有 NPC 的名字和昵称、事实卡里的家人（林爸、林妈、林子悦、Helen、Richard、Lottie、Biscuit、Pa Nok、Siobhan、Maureen 等）。不在名单里的 → 不过 |
| 承诺词 | 没有 [[INVITE]] 标记，却出现"回头发你""到时候告诉你""周X带你""I'll send you""I'll let you know"一类 → 不过 |
| 语言 | lang=en 的角色回复里有中文却没有「」 → 不过（试玩报告 14 条已有） |

- 白名单和承诺词表写在 `data/ai_guard.js`，策划可以往里加。
- 检查不通过的回复，记一条到 `S.aiRejects`（只存在本地，方便以后调规则）。

### 4. 记忆：AI 只记"真的发生过"的

- 给 AI 的上下文只放：聊天记录、【已发生】的剧情消息、当前阶段、玩家的基本信息（家乡、专业、tag、生日——生日要玩家在聊天里说过才放）。
- 不把"玩家没经历的剧情"放进上下文（比如还没触发的事件文本），免得 AI 提前剧透或者以为发生过。

## 三、策划这边写剧本的时候也遵守

- 新出现的家人、朋友、地点，先写进事实卡/人物关系表，再在剧本里用。
- 每个攻略对象的"不能编的"清单，写剧本时也不碰（例：Kieran 的爸爸，剧本也永远不写）。
