# 手机和友情（策划定稿，2026-11-17）

Cora 定的方向，给编程实现。和恋爱好感分开，互不影响。

## 一、手机

手机里的聊天 App 是微信＋Instagram 的合体，所有同学和生活里认识的人都在里面，互相能发消息、发动态。小红书照旧单独一个 App。

**有联系方式的人**（见过面才出现在通讯录）：

| 类别 | 人 | 备注 |
| --- | --- | --- |
| 攻略对象 | 学长、Ollie、Ploy、Kieran | 好感照旧 |
| 室友 | 陈思琪、周可欣、吴桐、Jake、Giulia、Mei | 只有同住的三个人在通讯录里，其余的在剧情里见过才加 |
| 组员 | Hannah、Ben | Ben 回得很慢，经常只回表情 |
| 生活 | 陈建国、赵子豪、Sophie、Mr. Khan | Mr. Khan 只聊房子的事 |
| 特殊 | Essay学姐 | 能聊，但没有友情值，只推进代写线 |

**没有联系方式的人**：Pike、Nikos、于晓、Marcia（老师只发邮件）；Dave、Linda（只在剧情里出现）。

**动态**（Ins／朋友圈那一栏）：有联系方式的人会发动态，内容由 API 生成；没有 key 时用固定内容。可以点赞、评论；评论和私聊一样算互动。

**邮件**：不做邮箱系统。只在剧情里弹出固定的邮件卡片（发件人、标题、正文），看完就关，不存档。剧本里写成【邮件：发件人｜标题】，后面跟正文。现在用到的有：出分通知、tutor 见面通知、Marcia 的几封、学校停课通知、学术诚信办公室的自动回复。

## 二、友情值

**谁有**：上面表里除了攻略对象和 Essay学姐 以外的人。老师没有。

**范围**：0–100。剧情里第一次认识时设为 10。

**怎么涨**：
- 剧情选项：±3～±10，写在文本里，记作〔友情·吴桐+5〕。
- 手机私聊、评论动态：AI 判断 +0～+2，每人每周算一次。
- 周末地点偶遇：+3（偶遇规则同攻略对象，一个地方一次只撞见一个人）。
- 同住的室友：每周自然 +0.5。

**会不会掉**：不自然下降（写作量和数值都简单一点）。剧情里可以扣。

**三档**：

| 档位 | 范围 | 效果 |
| --- | --- | --- |
| 认识 | 0–29 | — |
| 熟人 | 30–59 | 剧情里的一部分分支要这一档才出现（比如生病时吴桐送粥） |
| 朋友 | 60–100 | 每有一个“朋友”，每周孤独自然增长 −1，最多 −3；朋友是英国人或国际生的，每周融入 +0.3 |

**朋友事件**：每个人第一次到“朋友”档，触发一次小事件（一段，不出 CG）。只给下面这几个人写：陈思琪、吴桐、周可欣、Jake、Giulia、Mei、Hannah、陈建国。其余的人到 60 只有一条手机消息。

**结局**：不单独出结局。毕业离场那段，“朋友”档的人会来送你（文本按人写一句）；结局明信片背面列出朋友的名字。

## 三、和恋爱线的区别

- 友情值不算鱼塘值，不会翻车。
- 没有 CG。
- 手机里显示的是“友情”，不是“好感”，界面颜色区分开。

## 四、编程要做的

1. 通讯录按上表加人；每个人加一段聊天用的人设简介（策划这边补进 `data/characters.js` 的说明，编程先用现有设定）。
2. 加“动态”一栏：发动态、点赞、评论。
3. 加 `fr_xxx` 友情值（写法同 `aff_xxx`），三档效果按上表接进每周结算。
4. 剧情步骤加 `{ mail: { from, title, body } }`：弹邮件卡片。
5. 存档、对话记录里带上友情值和动态。
